Booking Lifecycle — Happy Path
From task creation to escrow release and rebooking
📋
Phase 1: Task Creation
Household initiates a service request
1
PREDICTED L4+ only
Auto-created by predictive scheduler after prior escrow release. Learns household's recurring cycle pattern.
POST /api/predictive/lock → locks to CREATED after lockAt
2
CREATED TaskStatus.CREATED
Household manually creates task, or PREDICTED task locks (past lockAt). Quotation linked if from quote.
POST /api/tasks | POST /api/predictive/lock
⚡ Autonomy Check
L3+ autonomy → auto-match fires immediately → skip to Phase 2
L1–L2 → household manually clicks "Start Matching"
↓Dispatch / Auto-Match
🔍
Phase 2: Matching & Dispatch
Vendor routing engine scores and assigns
3
MATCHING TaskStatus.MATCHING
Routing engine scores all ACTIVE vendors. Top vendor gets a Booking(status: assigned). Household sees "Searching for Provider" (vendor identity hidden).
POST /api/tasks/[id]/dispatch | GET /api/tasks/[id]/suggest-vendors
4
Booking Created assigned
Booking created with status "assigned". acceptTimeoutAt = now + 15 min. VendorHouseholdAffinity.bookingCount incremented.
PATCH /api/vendors/[id]/bookings/[bookingId]
↓Vendor Accepts (within 15 min)
✅
Phase 3: Vendor Acceptance
Vendor accepts the booking, escrow is held
5
ACCEPTED / SCHEDULED TaskStatus.ACCEPTED
Vendor clicks Accept. Booking → "accepted". Task → ACCEPTED (no scheduledStart) or SCHEDULED (has scheduledStart). Vendor identity revealed to household.
PATCH /api/vendors/[id]/bookings/[bookingId] (action: accept)
💰 Escrow Created Here
Escrow record created with state: HELD
Amount = task.amountCents
Commission = 10% (PLATFORM_COMMISSION_RATE)
↓Vendor Starts Work
🔧
Phase 4: Service Execution
Vendor performs the service
6
IN_PROGRESS TaskStatus.IN_PROGRESS
Vendor clicks "Start Work". Booking → "in_progress". actualStart recorded. Anomaly detection triggered. Household notified.
PATCH .../bookings/[id] (action: start)
7
COMPLETED TaskStatus.COMPLETED
Vendor marks complete (with optional completionNotes). Booking → "completed". actualEnd + completedAt recorded. Verification photos uploaded.
PATCH .../bookings/[id] (action: complete) | POST .../bookings/[id]/photos
↓Household Verifies Photos
📸
Phase 5: Verification
Household approves work quality
8
VERIFIED TaskStatus.VERIFIED
Household approves verification photos. All unverified photos marked verified. Autonomy promotion check runs (level-up possible).
POST /api/tasks/[id]/verify
↓Release Escrow
💳
Phase 6: Escrow Release
Payment released to vendor
9
ESCROW_RELEASED TaskStatus.ESCROW_RELEASED
Household clicks "Release Escrow" or Ops releases. Escrow → RELEASED. Task → ESCROW_RELEASED. REBOOKING_PROMPT notification sent.
PATCH /api/tasks/[id]/escrow (release) | PATCH /api/ops/escrow/[id] (release)
↓Rebooking Prompt
🔄
Phase 7: Rebooking
Cycle repeats for recurring services
10
New Task Created Cycle
Household rebooks → new CREATED task (cloned). L4+ households: predictive scheduler auto-creates PREDICTED task based on learned cycle → back to Phase 1.
POST /api/tasks/[id]/rebook
