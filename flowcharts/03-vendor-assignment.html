Phase 3: Vendor Response (3 Outcomes)
Vendor accepts, rejects, or times out
✅ Accept
Booking: assigned → accepted
Task: MATCHING → ACCEPTED (or SCHEDULED)
Escrow CREATED (state: HELD)
Vendor identity revealed to household
→ Proceed to service execution
PATCH .../bookings/[id] (accept)
❌ Reject
Booking: assigned → cancelled
Task stays in MATCHING
No escrow created
matchAttempts incremented
→ Auto-re-route or escalate
PATCH .../bookings/[id] (reject)
⏰ Timeout (15 min)
Booking: assigned → cancelled
Task stays in MATCHING
No escrow created
matchAttempts incremented
→ Auto-re-route or escalate
POST /api/tasks/timeout-check
↓If Rejected / Timed Out

Phase 4: Auto-Re-Routing
System tries next vendor or escalates to ops
3
Reassignment Decision
After vendor rejection or timeout, the system checks how many match attempts have been made.
matchAttempts < 5 (MAX_MATCH_ATTEMPTS)
New booking created for next-ranked vendor
15-minute timer restarts
→ Back to Phase 2
matchAttempts ≥ 5 OR no more vendors available
task.needsOpsIntervention = true
SYSTEM_ALERT notification created
→ Ops team manually intervenes (Phase 5)
↓If escalated
