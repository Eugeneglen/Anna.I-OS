Exception Flows

Dispute, cancellation, timeout & reassignment
A DISPUTE FLOW
1 Household Raises Dispute From IN_PROGRESS ACCEPTED SCHEDULED COMPLETED VERIFIED
2 Escrow Status DISPUTED
3 Resolution Paths
a) Resolve (Dismiss)
a Dispute Dismissed Household or ops dismisses
b Back to COMPLETED COMPLETED
c Escrow → HELD Payment resumes normal flow
b) Refund (Upheld)
a Ops Upholds Dispute Evidence supports household claim
b Stays DISPUTED DISPUTED
c Escrow → REFUNDED REFUNDED
B CANCELLATION FLOW
1 Ops Cancels Any non-terminal booking CANCELLED
2 Household Cancels Predicted Task Predicted task with cancelledAt timestamp PREDICTED
3 Vendor Decline / Rejection
matchAttempts < 5
a Auto Re-route Stays in MATCHING phase
matchAttempts = 5
b Escalate to Ops Flag: needsOpsIntervention
C TIMEOUT FLOW
1 15-min Accept Timer Expires Vendor did not respond in time
2 Auto-Cancel Booking Booking is automatically cancelled
3 Re-route or Escalate Same logic as vendor rejection
ℹ Follows the same re-routing / escalation logic as the Cancellation Flow vendor rejection path (matchAttempts threshold).
D REASSIGNMENT
1 Booking Cancelled No active bookings remain for the task
2 Task Resets to MATCHING Status reverts; new vendor search begins
3 New Vendor Search Excluding previously tried vendors from the candidate pool
ℹ Previously attempted vendors are excluded from future matching to avoid repeated failures and improve dispatch efficiency.
